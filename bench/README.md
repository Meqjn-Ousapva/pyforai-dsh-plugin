# Bench: anchors vs. structural editing vs. plain Python

This directory contains the executable form of the three-arm experiment
described in [`DESIGN.md`](DESIGN.md).

The harness is **model-agnostic**. It prepares identical run directories,
scores the artifacts an agent leaves behind, and aggregates the results. It
does not call an LLM. To run the experiment, point any agent runner at
`runs/<id>/prompt.md`; the harness will do the rest.

## Layout

```
bench/
├── DESIGN.md              # protocol, hypotheses, metrics, power analysis
├── README.md              # this file
├── harness.py             # init / score / report / list
├── tasks/
│   ├── W1_retry/          # write from scratch
│   │   ├── task.md
│   │   ├── tests_public.py
│   │   └── start.py       # empty
│   └── R1_retry_loop/     # structural refactor
│       ├── task.md
│       ├── tests_public.py
│       └── start.py
├── hidden/
│   ├── W1_retry.py        # copied into the run only at scoring time
│   └── R1_retry_loop.py
├── arms/
│   ├── A_no_anchors.md
│   ├── B_anchors.md
│   └── C_structural.md
├── runs/                  # generated; one directory per task × arm
│   └── <task>__<arm>/
│       ├── task.md
│       ├── tests_public.py
│       ├── start.py       # refactor tasks only
│       ├── solution.py    # the agent's artifact
│       ├── prompt.md      # the exact instructions for the agent
│       ├── arm.md
│       ├── run.json
│       ├── metrics.json   # written by `score`
│       └── ...            # agent logs
├── report.md              # generated by `report`
└── report.csv
```

## Tasks

| id | kind | what it stresses |
|---|---|---|
| `W1_retry` | write | `for` + `try/except` + closure; retry decorator with jitter |
| `R1_retry_loop` | refactor | replace a small loop body with retry logic |
| `R2_reconcile` | refactor | wrap an 8-line, 3-level nested block in `try/except`; per-account error isolation |

`R2_reconcile` was added after the first pilot showed a ceiling effect on the
two smaller tasks. It is a difficulty probe, not part of the original 2×3
design.

## Quick start

```bash
cd python-for-AI

# 1. create the 6 run directories and prompts
python bench/harness.py init

# 2. run one agent per run directory (any runner; see below)
#    the agent must produce runs/<id>/solution.py and pass tests_public.py

# 3. score all runs
python bench/harness.py score

# 4. aggregate
python bench/harness.py report
```

Inspect a prompt:

```bash
cat bench/runs/W1_retry__B/prompt.md
```

## Running an agent

The harness deliberately does not embed a model client. A run needs an agent
that can read/write files and execute commands. Give it this prompt:

```
You are running a controlled programming experiment. Work from the project
root /absolute/path/to/python-for-AI.

Your run directory is bench/runs/<id>.

1. Read bench/runs/<id>/prompt.md and follow it exactly.
2. Read bench/runs/<id>/task.md and bench/runs/<id>/tests_public.py.
3. Make bench/runs/<id>/solution.py pass the public tests (max 3 repairs).
4. Follow the logging instructions in prompt.md.
5. Do not read other runs, bench/tasks, bench/hidden, or bench/DESIGN.md.

When done, write bench/runs/<id>/summary.md and reply with that 3-line summary.
```

The pilot in this repository used six DSH subagents in parallel, one per
`runs/<id>` directory. The harness does not care which runner produced the
artifact.

## Scoring

`score` is deterministic. For each run it records:

| Field | Meaning |
|---|---|
| `syntax_ok` | `ast.parse(solution.py)` |
| `public_pass` | `python -m unittest tests_public` |
| `hidden_pass` | hidden test, copied into the run only at scoring time |
| `anchor_errors` | `pyforai check` errors in the final artifact |
| `anchor_count` | number of `# end ...` anchors |
| `loc` | non-blank lines of `solution.py` |
| `diff_added` / `diff_removed` | against `start.py` (or empty for write tasks) |
| `repair_attempts` | non-blank lines in `attempts.log` |
| `wall_time_s` | `finished_at.txt - started_at.txt` |
| `pyforai_calls` | lines mentioning `pyforai` in `commands.log` |
| `tampered_tests` | `tests_public.py` hash differs from `init` |

The hidden test is copied to `runs/<id>/test_hidden.py` immediately before it
runs, so it is not visible while the agent works.

## Adding a task

1. Create `tasks/<id>/task.md`, `tests_public.py`, and optionally `start.py`.
2. Put the hidden test at `hidden/<id>.py`.
3. Add `"<id>": {"kind": "write"|"refactor"}` to `TASKS` in `harness.py`.
4. `python bench/harness.py init --tasks <id>`.

Tests must import `solution` from their own directory; the harness runs them
with `cwd` set to the run directory.

## Interpreting the pilot

The pilot is **N=1 per task×arm cell**. It validates the pipeline and exposes
ceiling/floor effects. It cannot support significance claims. See
[`DESIGN.md`](DESIGN.md) §7 and §9 for the full study design and threats to
validity.
